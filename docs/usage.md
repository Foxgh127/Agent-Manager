# 使用与故障处理

## 数据位置

`CODEX_HOME` 优先于默认用户目录。相对的覆盖路径以用户主目录为基准，避免通过不同快捷方式启动时读取不同数据。安装包资源通过包路径或 PyInstaller 解包目录定位，不从任意当前工作目录读取。

Windows 凭据由 DPAPI 绑定当前用户保护。换电脑使用导出/导入；不要复制加密秘密文件期待直接解密，也不要把令牌、导出包上传到仓库。

## 网页余额与 403

点击刷新会优先访问站点支持的账号接口。0 是有效余额；缺失、失败和上次值分别显示。网站的脚本验证与身份过期是不同情况，403 验证页不会触发盲目换凭据或绕过网站限制。

“通过网页刷新”打开同账号的独立窗口。用户完成验证后进行身份回验和余额读取。已验证的窗口最多保留一个，隐藏后只用于用户显式刷新。切换身份、导航到其他来源、取消或退出管理器会释放。网站再次要求验证时继续由用户完成。

## 会话可见性与 API 格式

先确认选定的来源与模型可用，再使用会话维护入口检查索引。完整无状态历史遭遇不兼容加密推理项时，网关只在明确的输入错误响应后做一次同身份适配重试；原会话内容不变。

若会话只剩服务端游标或压缩密文，恢复原来源通常更可靠。应用不会假装知道丢失的原文，也不会在已经输出后重放整次请求。

## 备份

自动备份和恢复前原件共用最近三份不同内容上限。手动备份不自动到期。受保护的活动或失败事务备份暂时保留，并显示原因；恢复成功后解除相应保护并清理。

手动备份保存磁盘中的 `config.toml`，不包含编辑器尚未保存的草稿。恢复前会保存原件、检查指纹、回验写入；发生并发修改时停止覆盖。删除只接受本次列表的有效 ID，路径或内容变化后需重新检查。

## 采样与美元等值

有效校准区间保存在 Codex 用户数据目录，重开应用继续读取。同账号的重复激活不重建计数；短暂扫描不完整时保留有效样本，并在恢复后建立新的配对起点。应用关闭期间无法确认的用量不会强行连接成连续区间。

当前模型配置、套餐及额度周期分开校准；变化前的有效区间保留为历史，避免把不同负载混成一个固定额度。最多保留 48 个当前区间与 8 段历史，长期记录有容量上限。更多有效样本有助于修正当前负载的估算，但跨设备使用、模型或缓存比例变化仍会带来误差。

按已记录的实际型号分别计算：`未缓存输入 × 输入价 + 缓存输入 × 缓存价 + 输出 × 输出价`。缓存输入包含在输入中，推理输出包含在输出中，均不重复计数。金额按每百万 Token 的美元价格换算。

内置价目核实于 2026-09-10，支持 GPT-6 Astra 与 GPT-5.6 Sol、Terra、Luna。新记录按实际型号、单次输入是否超过 272K、服务档位及缓存读写分别计算；未知字段不补成零或默认短价。信息不完整时可以使用已声明假设下的条件区间，未定价型号和档位继续显示未知。[综合计算方法](quota-estimation.md)

卡片默认只显示“预计总额度”，至少需要 3 个完整区间、额度累计下降 6 个百分点；条件不满足时显示待校准。点击可查看记录依据、范围和跨周期比较。金额不是现金余额或账单；容量下降线索也不等于证明官方削减。

旧版已经清除的配对样本不能从一个当前余额数字恢复；新版保留仍在磁盘上的有效样本，并继续积累新证据。

## 打开应用与配置状态

模型总上下文、最大输入和客户端可用预算是不同限制；调度中心会显示设置值及预计可用值，详见 [窗口换算](context-window.md)。

启动时先读缓存，不自动执行全量诊断、在线更新检查和插件目录强制刷新。临时配置激活期间显示进度，完成后重新读取同步状态；原生子代理模式没有管理器说明标记是合法状态。

本地 CLI 版本和模型探测按安装文件身份缓存，最长保留 24 小时；安装变化、到期或主动刷新后重新探测。初次启动没有有效缓存时，版本与目录探测仍可能分别等待最多 10 秒和 30 秒。完整诊断的缓存过期会提示，其他真实问题仍保留在检查结果中。

应用的调用策略编辑区只展示正文；Codex“说明”还包含自动生成的调用规则、生命周期和实际路由。比较其中的 `Editable call strategy` 段落即可，不应把完整说明再次粘贴为策略正文。[策略结构](subagent-policy.md)

## 更新与版本重置

9.x 客户端不会把 1.0.0 视为更大的版本号，需要手动安装一次。1.x 发布包含独立代次标记，新客户端拒绝把旧 9.x 或旧缓存当作升级候选。后续版本继续使用内置 GitHub 发布源。

自动安装会先校验文件，再等待同一管理器实例完成配置恢复和退出。助手不能独立运行、目标不可写或回验失败时会停止更新并保留恢复信息。程序正在使用时不要强行删除它；结束旧进程后运行清理命令。

## 缺少组件

- 主界面缺少 WebView2/.NET 时可使用默认浏览器；网页登录仍需要支持的 WebView2 环境。
- 没有 Codex 时按需部署 CLI 或安装桌面版，不假设任何特定安装目录。
- Store CLI 不可用时不声称 Desktop 已是最新版。
- 不可写的安装目录无法原位替换 EXE，可改用个人可写目录。
