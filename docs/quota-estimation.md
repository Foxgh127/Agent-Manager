# 综合额度估算

卡片默认只有“预计总额度”：证据完整时显示估值，条件明确但信息不完整时显示区间，样本不足时显示“待校准”。点击后可查看口径、历史样本和容量变化线索。

## 单次费用与账号额度

`272K × 输入单价` 是一次请求的输入费用，不是账号总额度。例如标准短上下文、没有缓存读写且不计输出时：Luna 为 `$0.20 × 0.272 = $0.0544`，Sol 为 `$4 × 0.272 = $1.088`。输出按实际数量另计。[Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)、[Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)

本项目把完整记录的本机用量，与同一账号官方额度百分比的下降配对。例如一个完整区间实际用了 3 美元 API 等值、额度下降 3 个百分点，该区间支持约 100 美元的总等值推算。不会只用一个区间下结论，也不把订阅价格除以单价当固定 Token 上限。

## 模型、上下文与缓存

价格表核实于 2026-09-10，覆盖 GPT-6 Astra、GPT-5.6 Sol/Terra/Luna：

| 模型 | 普通输入 | 缓存读 | 缓存写 | 输出 |
| --- | ---: | ---: | ---: | ---: |
| Astra | $10 | $1 | $12.50 | $50 |
| Sol | $4 | $0.40 | $5 | $20 |
| Terra | $2 | $0.20 | $2.50 | $12 |
| Luna | $0.20 | $0.02 | $0.25 | $1.20 |

上表单位为每百万 Token、标准短上下文价。输入超过 272K 时，整次请求的输入与缓存费率乘 2、输出费率乘 1.5；Fast 按对应费率乘 2，Flex/Batch 按其公开费率。具体档位以返回证据为准，不能把请求中的 `auto` 当作实际 Standard。[官方价格](https://developers.openai.com/api/docs/pricing)、[Fast mode](https://developers.openai.com/api/docs/guides/fast-mode)

缓存读写从输入总数中分拆，不能再次叠加到总 Token；推理 Token 已包含在输出中，也不重复计费。长短档位在每个请求完成时确定，不能根据一天累计 Token 或设置的“1M 窗口”判断。[Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)

新记录保留上游返回型号、实际服务档位、单请求上下文档位和各类计量证据。旧日志缺少的字段仍是未知。条件区间只枚举声明的 Standard/Fast/Flex/Batch、长短上下文与可行缓存比例；不覆盖未定价 Ultrafast 或未知型号，不是无条件保证。工具、地域与未识别模态的附加费用不计入 Token 等值。

## 持续校准与下降线索

总额估算至少需要 3 个完整区间、累计下降 6 个百分点。计价版本和计数范围必须一致，区间的已定价 Token 差必须与校准 Token 差相等。条件区间使用可加总的同类记录分别求差，记录重分类、移除或新增无法解释的用量会中断配对。

严格比较还要求当前及至少两个不同历史额度周期各有 5 个完整区间、下降 15 个百分点，并保持账号、套餐、配置和相近模型/档位/上下文、缓存、输出、推理及平均请求量。条件价格范围不能作为削减证据。只有观察区间整体低于可比历史范围，才提示“可比容量下降线索”。

这仍不能证明官方削减：其他设备消耗、额度记账延迟和未匹配的工具使用会改变结果。官方也说明消耗随模型、任务和上下文变化。[Codex 定价与额度说明](https://learn.chatgpt.com/docs/pricing)

样本和历史跨重启保留；范围改变时重新建立起点，旧记录继续可见。存储有账号数、区间数、历史段数和文件大小上限，优先清理最老历史。旧版缺少计价证据的样本不会被强行转成精确美元样本。
